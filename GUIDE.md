# What to put in this portfolio

This repo is an **evidence portfolio**, not a finished-products gallery. Each claim needs inspectable proof.

## Recommended order

1. **Cybersecurity support assistant:** Begin with the included synthetic tickets. Run baseline and structured prompts, complete separate prediction CSVs and evaluate them. Update the project README with measured results.
2. **AI coding case study:** Choose one real Codex project. Add your actual brief, revisions, code or demo link, acceptance tests and what you changed.
3. **Multi-agent architecture:** Extend the existing design with interface contracts and a small prototype if you build one. Do not call it operational until tested.
4. **Model comparison:** Compare two models on the same coding task, with fixed requirements and multiple attempts.
5. **Prompt optimisation:** Isolate one prompt variable and measure whether it helps.

## How to add a finished project
- Copy `templates/project-case-study.md` to a new folder under `projects/`.
- Replace placeholders with the exact prompts you used and the actual evidence.
- Save screenshots in your project folder with meaningful filenames.
- Link source repositories and relevant commits, not just polished final screenshots.
- Keep failures and limitations visible.
- Change project status to **Completed** only when evidence is present.

## Important honesty checks
- A concept is not a working agent.
- An AI-written prompt may still demonstrate good delegation, but describe your own contribution.
- Do not invent model comparisons, certificates, accuracy scores or employment experience.
- Never publish API keys, private chats, credentials or other people's information.

## CV wording once your first real experiment is completed
"Built and documented an AI prompt engineering portfolio, including reproducible evaluations of structured prompts for fictional IT support classification. Published prompts, test data, results and analysis on GitHub."

Use measured figures only after you've run the tests.
